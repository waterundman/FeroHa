01 · 项目概述

现有"AI 笔记"工具的核心误区在于将 AI 生成内容与人类思考直接混排，导致知识污染与认知噪声。本项目通过将存储层、访问权限与数据流彻底分轨，使 AI 面作为人类面的知识扩展超集，而非侵入者。两者之间通过显式协议（PR 式 Merge）进行受控的知识跃迁。

字段内容
项目定位Local-first 桌面 IDE，兼具笔记管理与 AI 内容管理功能
核心问题AI 写作数据流量大、产出冗余，若与人类笔记混存会导致语料稀释与"AI 抢权"
解决思路物理隔离两面存储；AI 面仅持有读权限，人类面绝对控制写入；通过 Diff/Merge 协议实现单向知识提炼
个人需求来源Obsidian Vault 随开发迭代持续膨胀，现有 skill 写入机制不可预期，需将 AI 数据流与人类写作彻底解耦

03 · 技术选型
层级选型说明
宿主框架 Tauri 2.0 跨平台桌面端，未来可编译移动端；相比 Electron 显著降低内存占用
核心逻辑层 Rust 处理高 CPU 消耗的文件监听、AST 解析、向量计算、Agent 调度
UI 表现层 TypeScript + React / Vue3 编辑器内核：ProseMirror 或 CodeMirror 6（AST 拦截支持好）
人类面存储 本地文件系统 .md 纯文本抗脆弱，文件系统即数据库，LLM 的最佳通用接口
AI 面向量库 LanceDB / Qdrant 嵌入式，Rust/C++ 底层，查询速度快；LanceDB 优先（嵌入零依赖）
AI 面关系图 SQLite + JSON 轻量图结构，存储幽灵节点与锚点关系映射
文件监听 Rust notify 实时监控 Vault 变动，触发增量 AST 解析
Markdown 解析 Rust pulldown-cmark 毫秒级解析为 AST，提取 Heading / Block / Link
LLM 接入 LLM Router API 支持本地模型加载器与云端闭源模型，解耦可替换
技术选型原则：Rust 将沉重的 AI 处理全部压在"水面之下"，前端只暴露最纯净的 Markdown 与极客风格的 CLI。
04 · 核心模块
MOD-01
人类面存储与解析
文件监听 → AST 解析 → 静默语义分块（Chunking）→ 打哈希时间戳 → 向量化准备。notify 实时监控，pulldown-cmark 毫秒级解析。
notify pulldown-cmark Human-only Write
MOD-02
AI 面 Agentic 后台
Rust 后台线程异步调度。以 [[锚点]] 为触发器，执行 Web 检索 / Arxiv 抓取 / API 调用，产出物以"幽灵节点"形式写入 VectorDB，绝不直接修改人类 Markdown。
LanceDB RAG Ghost Nodes
MOD-03
AgentCLI 指令层
前端监听 / 起手式弹出补全提示。指令通过 Tauri invoke 传递给 Rust，异步执行后以 emit_all 推回前端状态。键盘驱动，无干扰写作。
Tauri IPC invoke emit_all
MOD-04
Visual Diff & Merge
PR 式知识吸收机制。Rust 维护当前 AST 与 AI 增量 AST。前端双栏或行内高亮差异，用户原子化逐句 Accept / Reject，采纳后 Rust 重写物理 .md 文件。
Diff Engine Merge Gate Block-ID Hash
MOD-05
Dreaming 分时整理
AI 面在特定时间段（低活跃窗口）自动对已积累的内容进行重组、归类与压缩，防止 AI 面数据熵增失控。类比"睡眠记忆巩固"机制。
Scheduled Content Compression
MOD-06
双图层知识图谱
人类面使用标准 Markdown 渲染器；AI 面使用富表现力前端组件（图表、思维导图、3D 节点），专门呈现高维或复杂结构数据，避免信息过载。
Graph View Dual Render 3D Node
05 · 核心工作流
1
Write & Map · 写作与静默映射
用户在编辑器中写作 → Rust 监听到保存 → pulldown-cmark 解析 AST → 提取关键 Block 与链接锚点 → 生成向量 → 存入本地 LanceDB。用户无感知。
2
CLI Trigger · 指令下达
用户输入 /agent fetch-papers --topic "..." --link-to [[当前文档]] → 前端封装为 IPC JSON → invoke 传给 Rust → Rust 开启异步任务 → UI 显示 [Agent 运行中...] → 用户继续无干扰写作。
3
Graph Population · 图谱补全
Rust Agent 调用 LLM 与检索引擎 → 获取文献 / 资料 → 切块 → 在 VectorDB + GraphDB 中生成"幽灵节点" → 与用户文档建立单向链接。不写入任何人类面文件。
4
Review & Merge · 审阅与合并
系统通知抓取完成 → 用户点击 Review → 前端调出 Visual Diff 组件 → 双栏对比 AI 增量与原文 → 用户逐句 Accept / Reject → 点击 Merge → Rust 将采纳内容写入物理 .md → 知识完成人类面跃迁。
5
Dreaming · 分时整理（后台）
在用户低活跃时间窗口，AI 面自动对积累的幽灵节点进行重组、压缩与主题归类，保持 AI 面数据的精炼性，防止熵增。
06 · 关键挑战与策略
挑战风险等级当前策略
Markdown AST 差异合并精确性
自然语言无大括号边界，段落对齐困难		 High 引入 Block 级 ID（隐式哈希值 ^abc12），Diff 引擎按 Block ID 精准对齐，避免错位
高频编辑 IPC 通信开销
频繁按键触发大量序列化导致卡顿		 Med 前端编辑器与 Rust 核心之间增加 Debounce 防抖，仅在输入停顿（idle）时执行增量解析与向量同步
AI 面上下文感知精度
避免纯关键词 RAG 导致生硬匹配		 Med 以 AST 逻辑大纲而非关键词作为检索锚点，结合图结构进行局部语义理解
AI 面数据熵增
幽灵节点持续积累，质量稀释		 Low Dreaming 定时压缩与归类机制，保持 AI 面数据精炼度

参照借鉴要素本项目差异
